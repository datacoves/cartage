# Cartage v0.1 — Design

Date: 2026-09-30
Status: Approved in brainstorming, pending written-spec review

## 1. Purpose

Cartage is an open-source, client-agnostic CLI for declarative data migrations: sources, destinations and
pipelines are described in YAML, custom logic is plain Python referenced from YAML, pipelines run locally for
testing and deploy to an orchestrator.

It generalizes the J&J-specific MDE (`../mde`), keeping what worked (YAML-driven pipelines, per-environment
connections, dlt, Airflow) and dropping what did not (client metadata baked into the library, per-source Jinja
templates generating pipeline code, a monolithic render controller).

Engines (dlt first) and orchestrators (Airflow first, Prefect later) are pluggable adapters.

### v0.1 success criteria

A recordable demo for prospective customers, with no real SAP system available:

1. `cartage init demo` scaffolds a working project.
2. `cartage validate` / `plan` show a readable, colored check and a dry-run preview (record before/after
   transforms, resulting BAPI payload).
3. `cartage run pipelines/materials.yaml --env dev` loads CSVs (local folder or S3) through Python transforms into
   a **mock SAP** via `BAPI_MATERIAL_SAVEDATA`, with live progress and a summary including deliberate BAPI errors.
4. A second run with `incremental: true` skips already-processed files.
5. `cartage generate --target airflow` emits a DAG that passes `airflow dags test`; image/operator are
   configurable from YAML and the template is overridable.
6. Secrets never appear in YAML, generated files, or output.

### Out of scope for v0.1

Real SAP connectivity (RFC transport is a stub), OData transport, create-only BAPIs (need per-record dedupe
keys), cloud secret vaults, Prefect, a local Airflow stack (Docker/UI), code export to standalone scripts, Arrow
batches, row-level cursors on file sources.

## 2. Key decisions

| Decision | Choice | Reason |
|---|---|---|
| Execution model | **Runtime interpretation.** `cartage run` builds the pipeline in-process from adapters; generated DAGs are thin and call `cartage run`. | Local test runs the exact code production runs; adapters are testable Python, not templates. Cost: Cartage (and the project's `transforms/`) must be on the worker. |
| Transformations | Python functions referenced as `module:function` from YAML; three step kinds: `map`, `filter`, `batch`. No YAML transformation DSL. | Transformations in YAML don't scale; Python is the extension language. dlt engine maps steps to dlt's native `add_map`/`add_filter`/`add_yield_map`. |
| dlt sources | `type: dlt` source wraps any dlt source/resource by reference. | Reuses dlt's source ecosystem; makes "built on dlt" concrete. |
| Incremental | File-level (skip processed files) for filesystem/S3; dlt's own `incremental` for dlt sources. | Covers "new extracts land in a bucket" and cursor-based sources without inventing a cursor engine. |
| State storage | Configurable per env: local path or a prefix on a connection (e.g. S3). State saved **only when a run has zero record errors**, unless `--advance-state`. | Ephemeral Airflow workers lose local state; advancing past rejected records would silently drop them. Relies on upsert-style BAPIs being idempotent. |
| SAP cartagetion | BAPI-shaped destination with pluggable **transport**; v0.1 ships `mock` (in-process or HTTP server). | No SAP instance available; BAPI semantics (`BAPIRET2`, commit/rollback) keep the demo realistic and the YAML stable when `rfc`/`odata` arrive. |
| Demo scenario | Material master via `BAPI_MATERIAL_SAVEDATA`. | Flat structure, classic migration example, create-or-update semantics. |
| Airflow proof | Generate DAG + `airflow dags test`. | Proves the DAG runs without maintaining a Docker stack. |
| DAG customization | YAML settings (operator import path, operator args, k8s image) → overridable Jinja template with blocks → custom orchestrator plugin. | Each layer covers more cases at more cost; most users stop at YAML. |
| Secrets | `${secret:...}` / `${env:...}` references; providers: env vars and git-ignored `.cartage/secrets.yaml`. Pluggable provider interface. | Minimal and engine-agnostic (not tied to dlt's secrets system). |
| Plugins | Python entry points, four groups. | Third parties add adapters without forking. |

## 3. User-facing files

A user project:

```
cartage.yaml              # project settings: environments, defaults, state, orchestrator settings
connections.yaml          # named connections, config per environment, no secret values
.cartage/secrets.yaml     # git-ignored local secret values
.cartage/state/           # git-ignored local state (dev default)
.cartage/rejects/         # git-ignored rejected records per run
pipelines/
  materials.yaml
transforms/
  materials.py            # user Python referenced from pipelines
templates/airflow/        # optional DAG template override
data/
  materials/materials.csv
```

### 3.1 `cartage.yaml`

```yaml
project: demo
environments: [dev, prd]
default_env: dev
defaults:
  engine: dlt
state:
  dev: { path: .cartage/state }
  prd: { connection: materials_s3, prefix: cartage/state/ }
orchestrators:
  airflow:
    dags_dir: dags
    operator: airflow.operators.bash:BashOperator   # import path of an operator accepting bash_command
    operator_args: { retries: 2 }                   # passed through as kwargs
    image: myregistry/cartage-worker:0.1            # optional; KubernetesExecutor pod_override
    default_args: { owner: data-team }
```

`state` is optional; default for every env is `{ path: .cartage/state }`.

### 3.2 `connections.yaml`

```yaml
connections:
  local_files:
    type: filesystem
    envs:
      dev: { path: ./data }
  materials_s3:
    type: s3
    envs:
      dev:
        bucket: demo-dev
        region: eu-west-1
        access_key_id: ${secret:aws.access_key_id}
        secret_access_key: ${secret:aws.secret_access_key}
  sap_erp:
    type: sap
    envs:
      dev: { transport: mock, client: "100" }                 # in-process mock
      # dev: { transport: mock, url: http://localhost:8765 }  # external mock server
      prd:
        transport: rfc
        ashost: sap.example.com
        sysnr: "00"
        client: "100"
        user: ${secret:sap.user}
        passwd: ${secret:sap.passwd}
```

A connection is `type` + one config per environment. Selecting an environment a referenced connection lacks is a
validation error.

### 3.3 `pipelines/materials.yaml`

```yaml
name: materials_to_sap
source:
  connection: local_files       # or materials_s3
  format: csv
  path: materials/*.csv
  incremental: true             # skip files already processed
transforms:
  - map: transforms.materials:normalize_uom
  - filter: transforms.materials:is_active
  - batch: transforms.materials:dedupe
    with: { key: material }
destination:
  connection: sap_erp
  bapi: BAPI_MATERIAL_SAVEDATA
  mapping:                       # record field -> BAPI PARAM.FIELD ; PARAM[] = table parameter row
    material:    HEADDATA.MATERIAL
    industry:    HEADDATA.IND_SECTOR
    type:        HEADDATA.MATL_TYPE
    description: MATERIALDESCRIPTION[].MATL_DESC
    uom:         CLIENTDATA.BASE_UOM
  constants:                     # fixed values merged into every call
    MATERIALDESCRIPTION[].LANGU: EN
    HEADDATA.BASIC_VIEW: X
  commit: per_record             # per_record | per_batch | none
engine: dlt                      # optional; falls back to cartage.yaml defaults.engine
schedule:
  airflow:                       # presence enables DAG generation; keys override cartage.yaml orchestrators.airflow
    schedule: "0 3 * * *"
    tags: [sap]
    image: myregistry/cartage-sap:0.1
    operator_args: { pool: sap }
```

### 3.4 Secrets

- Syntax: `${secret:<dotted.key>}` looks up providers in order; `${env:VAR}` reads an environment variable.
- Provider order: environment variable `CARTAGE_SECRET__<KEY>` (dots → `__`, upper-cased), then
  `.cartage/secrets.yaml` (nested YAML matching the dotted key).
- Resolution happens only at run time, after environment selection, and only for connections the pipeline uses
  (including the state connection). A missing secret is an `CartageError` naming the reference, file, and line.
- Output masks resolved secret values as `****` (`plan`, `connections list`, errors, logs).
- In Airflow, the worker supplies `CARTAGE_SECRET__*` env vars (from Airflow Variables/Connections or the
  deployment's secret store). Generated DAGs never embed secrets.

### 3.5 Transforms

Steps run in order between source and destination. Each step names exactly one kind and a `module:function`
reference; optional `with:` is passed as keyword arguments; optional `on_error: fail` (default `record`).

| Kind | Signature | Use |
|---|---|---|
| `map` | `f(record: dict, **with) -> dict` | reshape/clean one record |
| `filter` | `f(record: dict, **with) -> bool` | drop records (`False` = drop, counted as `filtered`) |
| `batch` | `f(records: list[dict], **with) -> Iterable[dict]` | dedupe, split, enrich, pandas/polars work |

```python
# transforms/materials.py
def normalize_uom(record):
    record["uom"] = {"PCS": "EA", "KGS": "KG"}.get(record["uom"], record["uom"])
    return record

def is_active(record):
    return record.get("status") != "obsolete"

def dedupe(records, key):
    seen = {}
    for r in records:
        seen[r[key]] = r
    return seen.values()
```

- The project root is prepended to `sys.path`, so `transforms/` needs no installation.
- `validate` imports each reference and checks it is callable with the kind's arity; failures point at the
  YAML file and line.
- Exceptions: with `on_error: record` (default), a `map`/`filter` exception becomes a `RecordError`
  (`stage: transform`, source row, exception message) and the run continues; a `batch` exception fails every
  record in that batch. With `on_error: fail`, the run aborts (exit 3).
- Both engines produce identical results: the `python` engine applies steps in its loop; the `dlt` engine
  attaches them as `add_map` / `add_filter` / `add_yield_map` on the resource.

### 3.6 dlt sources

```yaml
source:
  type: dlt                              # no connection needed
  ref: sources.legacy_erp:materials      # user module, or a dlt verified source import path
  with: { base_url: "${env:ERP_URL}" }   # kwargs for the source function; secret refs allowed
  incremental: { cursor: updated_at, initial: "2024-01-01" }
```

- `ref` points at a function returning a dlt source or resource; it is called with `with` kwargs.
- `incremental` is applied to every selected resource via
  `resource.apply_hints(incremental=dlt.sources.incremental(cursor, initial_value=initial))`. Sources that
  already define their own incremental in code simply omit `incremental` from YAML.
- `type: dlt` with `incremental` requires `engine: dlt` (validation error otherwise). Without `incremental`, the
  `python` engine can iterate it too.

### 3.7 Incremental loads and state

- **Files** (`filesystem`, `s3`, `incremental: true`): the source skips files whose `(path, fingerprint)` is in
  state; fingerprint = mtime+size (filesystem) or ETag (S3). Re-uploading a fixed file changes the fingerprint,
  so it is processed again.
- **dlt sources**: dlt manages the cursor inside its pipeline state.
- **State store**: per env, `{ path }` (local directory) or `{ connection, prefix }` (a connection whose adapter
  implements state get/put; v0.1: `filesystem`, `s3`). Stored per pipeline: Cartage's JSON state (processed
  files) plus a tarball of the dlt pipeline working directory.
- **Lifecycle**: before a run, state is loaded; the `dlt` engine always runs in a temporary `pipelines_dir`
  restored from state. After the run, state is saved **only if the run had zero record errors**, or if
  `--advance-state` is passed. The run summary states whether state advanced.
- **Rejects**: every run with record errors writes them to `.cartage/rejects/<pipeline>/<run_id>.jsonl`
  (source row, stage, message, BAPI return).
- Ceiling: re-sending successful records on the next run is safe only for create-or-update BAPIs such as
  `BAPI_MATERIAL_SAVEDATA`. Create-only BAPIs will need per-record dedupe keys (future).

## 4. CLI

Typer + Rich. Global flags: `--project-dir` (default: nearest ancestor containing `cartage.yaml`),
`-v/--verbose`, `--debug` (tracebacks), `--no-color`. `validate`, `plan`, `run` accept `--json`.

| Command | Behavior |
|---|---|
| `cartage init [dir]` | Scaffold the demo project (§3 files, sample CSV of ~20 materials incl. 2–3 invalid rows and one obsolete row, `transforms/materials.py`, `.gitignore` for `.cartage/`). Refuses to overwrite. |
| `cartage validate [pipeline...] [--env E]` | Schemas, connection refs, env availability, secret resolvability, adapter configs, transform references, BAPI mapping targets vs bundled metadata, engine/source compatibility. Rich tree ✔/✘. |
| `cartage plan <pipeline> [--env E] [-n 3]` | Dry run: resolved connections (masked), adapters, files that incremental would process/skip, and for the first N records: source record → transformed record → BAPI payload. Writes nothing, touches no state. |
| `cartage run <pipeline> [--env E] [--advance-state] [--full-refresh]` | Execute. Live progress; summary table (read / filtered / sent / ok / warning / error, state advanced yes/no); error table (row, stage, `BAPIRET2` type+id+number, message). `--full-refresh` ignores existing state. |
| `cartage state show <pipeline> [--env E]` | Show stored state (processed files, dlt cursor values, last run). |
| `cartage state reset <pipeline> [--env E]` | Delete stored state after confirmation (`--yes` to skip). |
| `cartage generate --target airflow [-o DIR] [--check] [pipeline...]` | Write one DAG per pipeline with `schedule.airflow`. `--check`: exit 1 if files on disk differ from what would be generated. |
| `cartage generate --target airflow --show-context <pipeline>` | Print the template context for a pipeline (for template authors). |
| `cartage connections list [--env E]` | Connections, types, envs (secrets masked). |
| `cartage connections test <name> [--env E]` | Call the adapter's `check()`. |
| `cartage sap mock [--port 8765]` | Run the mock SAP HTTP server in the foreground, logging each BAPI call and its `BAPIRET2` result. |
| `cartage plugins` | Discovered adapters per kind with package of origin. |

Exit codes: 0 all ok · 1 record errors · 2 config/usage error · 3 transport/connection failure or
`on_error: fail` abort.

Error display: `CartageError` renders as one red panel (message + hint), no traceback unless `--debug`.

## 5. Architecture

### 5.1 Package layout

```
src/cartage/
  cli.py                 # Typer commands; thin
  ui.py                  # shared Rich console, tables, panels, progress, error rendering
  config.py              # Pydantic models for cartage.yaml, connections.yaml, pipelines; YAML load with line info
  secrets.py             # reference parsing + resolution; providers: env, file
  registry.py            # entry-point discovery for the four plugin groups
  core.py                # Protocols, run_pipeline(), RunResult, RecordError, CartageError
  transforms.py          # reference loading, signature checks, step application (python engine)
  state.py               # state store (local path / connection-backed), load/save, rejects writer
  scaffold/              # files copied by `cartage init`
  adapters/
    sources/filesystem.py
    sources/s3.py
    sources/dlt.py
    destinations/sap/destination.py
    destinations/sap/mapping.py
    destinations/sap/transports/mock.py      # in-process mock + HTTP server
    destinations/sap/transports/rfc.py       # stub: raises CartageError("rfc transport not available in v0.1")
    destinations/sap/bapi_meta/BAPI_MATERIAL_SAVEDATA.yaml
    engines/python.py
    engines/dlt.py
    orchestrators/airflow.py
    orchestrators/templates/cartage/airflow_dag.py.j2
tests/
```

### 5.2 Adapter contracts (`core.py`)

```python
class Source(Protocol):
    def __init__(self, config: dict, options: dict): ...     # options = pipeline `source` block minus connection
    def check(self) -> None: ...                             # raise CartageError if unreachable
    def read(self, state: dict) -> Iterator[list[dict]]: ... # batches; may record pending progress in `state`

class Destination(Protocol):
    def __init__(self, config: dict, options: dict): ...
    def check(self) -> None: ...
    def preview(self, records: list[dict]) -> list[dict]: ...   # payloads, no side effects (plan)
    def write(self, batch: list[dict]) -> BatchResult: ...      # record errors returned, not raised

class StateBackend(Protocol):                                   # implemented by filesystem and s3 adapters
    def get(self, key: str) -> bytes | None: ...
    def put(self, key: str, data: bytes) -> None: ...
    def delete(self, key: str) -> None: ...

class Engine(Protocol):
    def run(self, pipeline: Pipeline, source: Source, transforms: list[Step],
            destination: Destination, state: PipelineState,
            on_progress: Callable[[BatchResult], None]) -> RunResult: ...

class Orchestrator(Protocol):
    def generate(self, project: Project, pipelines: list[Pipeline]) -> dict[Path, str]: ...  # path -> content
```

`Source.read` mutates only the in-memory `state` dict; persistence is decided by `run_pipeline` (§3.7). The dlt
source adapter exposes the dlt source object to the dlt engine instead of batches; the python engine iterates it.

Each adapter may declare a Pydantic `Config` model; `registry` validates connection configs against it.

Entry-point groups: `cartage.sources`, `cartage.destinations`, `cartage.engines`, `cartage.orchestrators`.
Built-ins register in Cartage's own `pyproject.toml` exactly like third-party plugins.

### 5.3 Run data flow

1. Locate project; load and validate `cartage.yaml`, `connections.yaml`, the pipeline file.
2. Select env; pick each referenced connection's env config (source, destination, state).
3. Resolve secret references in those configs.
4. Look up adapters; validate adapter configs; load transform references.
5. Load pipeline state (unless `--full-refresh`).
6. Engine streams: `source.read(state)` → transforms → `destination.write(batch)`.
   - `python`: plain loop.
   - `dlt`: source wrapped as `@dlt.resource` (or the referenced dlt source), transforms attached natively, routed
     to a `@dlt.destination` sink whose callback calls `destination.write()`. Temporary `pipelines_dir`
     restored from state; telemetry disabled.
7. SAP destination, per record: mapping + constants → BAPI params; transport call; parse `BAPIRET2`; commit per
   `commit` mode (`per_record`: commit on success, rollback on error; `per_batch`: one commit if the batch had no
   errors, else rollback and report every record in the batch; `none`: never commit).
8. Write rejects; save state if zero record errors or `--advance-state`; return `RunResult`; `ui` renders;
   CLI sets exit code.

### 5.4 SAP mapping

- `PARAM.FIELD` sets a structure field; `PARAM[].FIELD` sets a field on the single row of a table parameter
  (v0.1: one row per record; multi-row grouping is future).
- `constants` use the same target syntax.
- Unmapped record fields are ignored; `validate` warns about them when the source schema is known (CSV header).
- Targets are checked against `bapi_meta/<BAPI>.yaml` (parameter kind, fields, max length, allowed values).

### 5.5 Mock transport

- `transport: mock` without `url` → in-process; with `url` → HTTP POST `{bapi, params}` to the mock server,
  which returns `{"RETURN": [BAPIRET2...]}`.
- Validation against bundled metadata yields realistic messages, e.g. `E MM 102 Material type ZXX does not
  exist`, `E MG 144 Field MATERIAL exceeds length 18`; success `S MM 356 Material 100001 created`.
- In-memory store: saving an existing material returns `S` "changed" (create-or-update semantics).
- `BAPI_TRANSACTION_COMMIT` / `ROLLBACK` accepted and logged.

### 5.6 Airflow generation

- One DAG per pipeline with `schedule.airflow`; one task running
  `cartage run <pipeline path> --env {{ var.value.get('cartage_env', 'prd') }} --project-dir <dir>`.
- Settings merge: built-in defaults ← `cartage.yaml` `orchestrators.airflow` ← pipeline `schedule.airflow`
  (scalars replace, dicts merge by key).
  - `operator`: import path of an operator accepting `bash_command` (e.g.
    `operators.datacoves.bash:DatacovesBashOperator`).
  - `operator_args`: rendered as kwargs.
  - `image`: rendered as `executor_config={"pod_override": k8s.V1Pod(spec=V1PodSpec(containers=[V1Container(name="base", image=...)]))}`.
  - `schedule`, `tags`, `default_args`, `catchup` (default `False`), `dag_id` (default: pipeline name).
- Template: built-in `cartage/airflow_dag.py.j2` with blocks `imports`, `default_args`, `dag`, `task`, `extra`.
  Jinja `ChoiceLoader` checks `<project>/templates/airflow/` first, so `templates/airflow/dag.py.j2` replaces the
  default, and may `{% extends "cartage/airflow_dag.py.j2" %}` to override single blocks.
- Output: header comment ("generated by cartage — edit YAML/templates, not this file"; notes that the project
  directory incl. `transforms/` must be deployed with it), deterministic ordering, no secrets.
- Verified by `airflow dags test <dag_id>` in an optional test.

## 6. Errors and exit codes

| Class | Examples | Handling | Exit |
|---|---|---|---|
| Config / usage (`CartageError`) | bad YAML, unknown connection, missing env, unresolved secret, unknown adapter, bad transform ref, dlt incremental on python engine | red panel with hint, before any data moves | 2 |
| Record-level | `BAPIRET2` type `E`/`A`; transform exception (`on_error: record`) | collected, run continues, rejects file, state not advanced | 1 |
| Fatal run | transport/connection failure, state store unreachable, transform with `on_error: fail` | abort, report what was committed so far, state not advanced | 3 |

## 7. Testing

- pytest via `uv run pytest`.
- Unit: mapping (targets, table params, constants), secret resolution/masking, config models and error
  locations, transform loading/signature checks/error handling, mock `BAPIRET2`, commit modes, settings merge
  for Airflow, state save rules.
- End-to-end, parametrized over `python` and `dlt` engines: `init` → `run --env dev` against the in-process mock;
  assert counts, filtered row, rejects file, exit 1, state not advanced; `--advance-state` advances; after
  fixing the bad rows' file, a rerun processes only that file.
- dlt source: a tiny in-test dlt resource with `incremental` cursor; second run loads only newer rows.
- S3 source and S3 state backend: `moto`.
- Airflow: `generate` snapshot test, `--check`, template block override, `image` rendering; `airflow dags test`
  skipped when Airflow is not installed.

## 8. Packaging

- Python ≥ 3.11, `uv`, `pyproject.toml` (hatchling), Apache-2.0.
- Core deps: `typer`, `rich`, `pydantic`, `ruamel.yaml`, `jinja2`, `httpx`.
- Extras: `cartage[dlt]`, `cartage[s3]` (boto3), `cartage[airflow]` (+ `kubernetes` for `image`), `cartage[all]`.
- Console script: `cartage = cartage.cli:app`.
